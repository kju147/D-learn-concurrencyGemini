# 课程设计：从并发零起点到工程熟练

> 外部来源（另一分析服务），2026-10-09 交付，已采纳为课程 v2 基线。出处与采纳边界见 `docs/PROVENANCE-CURRICULUM-V2.md`。

范围以 `curriculum/curriculum-v2.json`（对方称 app/curriculum.json）、coverage-ledger.json 为准；学习顺序以 learning-design.json 为准。当前 14 个模块、155 个知识点是规划范围，课程验收仍为 0。教学产品呈现和制作方式以 LEARNING-EXPERIENCE-DESIGN.md（未附）为准。

## 课程的终点

学习者能把一个业务约束变成并发协议，解释安全性与活性，在失败、取消、过载和关闭时保持协议成立，并用规范、受控反例、运行证据和测量支持选型。会复述 API 或在单次运行中得到正确输出不能算熟练。

原四册笔记保留来源对账，教学顺序与案例重新设计。Java SE 25 正式规范和 API 是主线；实现解释固定 JVM 构建与源码版本；预览、历史和第三方库各有独立环境。

## 六个能力阶段

模块是内容归档，阶段是学习路线。知识点先修递归补齐；线程池使用不再被 AQS 全章阻挡，测试方法从第一阶段开始。已有经验者用同样的实作诊断免修，不能按头衔从某一章开始跳读。

| 阶段 | 达成能力 | FlashFlow 增量 |
|---|---|---|
| S1 观察与实验 | 观察线程、安排交错、处理失败与退出，知道测试的证据边界 | 任务骨架、同步点、实验日志 |
| S2 状态与内存 | 找出整个业务操作的原子边界，解释对象身份、互斥、安全发布与不变量 | 单实例库存预留与对账 |
| S3 协作与资源 | 写可关闭有界队列，控制执行器、许可和下游容量 | 有界接入、排队、租约和停机 |
| S4 编排与现代并发 | 全局 deadline、异常、取消、任务退出；使用 JDK25 正式虚拟线程与 ScopedValue | 聚合接口，平台线程与虚拟线程对照 |
| S5 集成与生产 | Spring 边界、多实例、幂等、容器容量、观测和故障恢复 | 可运行服务与正确性、容量报告 |
| S6 机制与选修 | 深化锁、CAS、容器、JMM 测试，选择一个架构支线 | 热点优化或事件驱动/低延迟分支 |

这不是把 JMM、测试、关闭各讲一次就结束。每个阶段都重新检查状态/任务/许可所有权、业务不变量、失败与退出、证据边界以及迁移题。第一次用到 CountDownLatch 或 happens-before 时提供短桥接课，之后再系统深化。

## 六个正式专题

| 专题 | 定位 | 新增知识点与实践 |
|---|---|---|
| 完成顺序与竞速 | 主线必修 | CompletionService、invokeAll/invokeAny 比较，首个有效报价、全部失败、deadline 与剩余任务清理 |
| 事件循环与调度 | 边界知识必修，框架开发选修 | NIO/Netty 事件循环、Reactor 调度、背压、阻塞适配与上下文 |
| 单写者与高性能管线 | 设计取舍必修，低延迟实现选修 | 单写者、按键分区、批处理、环形缓冲区、Disruptor 依赖与等待策略 |
| 随机与实验重现 | 主线必修 | ThreadLocalRandom、任务随机流、种子与交错轨迹、故障注入、安全随机边界 |
| 回调重入 | 主线必修 | 内联完成、锁内外调用、半完成状态、通知顺序与异常协议 |
| 容器与容量 | 生产主线必修 | CPU 配额、JVM 可见处理器、throttling、载体线程、数据库连接与接入预算 |

专题都有独立目标、交互、练习、迁移与复习问题，详见覆盖报告。采用外部框架前固定版本，不能用浮动文档或浏览器模拟代替集成实验。

CompletionService 的课程依据其正式 API（JDK 25 docs）；线程边界分别对照 Netty EventLoop 与 Reactor 调度文档。环形管线采用 Disruptor 用户指南，容器实验对照 JDK 25 java 命令文档。这些是来源入口，不表示相应专题已完成开发。

## 案例和项目

每节课的案例先给出业务规则，再选择技术：库存预留、订单状态流转、配置快照、连接租约、聚合报价、批量导入、热点缓存和消息幂等。对比方案必须改变一个明确因素，如锁范围、状态拥有者、队列容量或失败政策；不凭更复杂的写法制造高级感。

FlashFlow 贯穿订单履约，同一领域逐步演进：库存 → 有界接入 → 报价/风控聚合 → 弹性与幂等 → 虚拟线程迁移 → 多实例与生产证据。数据库条件更新承接跨进程库存一致性；进程内锁的作用范围必须讲清。Reactor 与 Disruptor 用分支比较，不强行和主服务混成一个方案。所有必修能力要有自然场景，所有选修方案要有选型与代价报告。
